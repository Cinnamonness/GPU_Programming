### Пояснения к полученным параметрам

- Device has Compute Capability — вычислительная способность GPU, определяет поколение архитектуры (важно при выборе версии CUDA и совместимости).

- Device name - название видеокарты.

- Total global memory - объём глобальной памяти GPU.

- Shared memory per block - объём разделяемой памяти, доступной на один блок потоков.

- Registers per block - количество регистров, доступных на блок.

- Warp size - размер варпа (группы потоков, исполняемых одновременно).

- Max threads per block - максимальное число потоков в одном блоке.

- Max threads dimensions - допустимые размеры блока по осям X, Y, Z.

- Max grid size - максимальные размеры сетки блоков.

- Clock rate - тактовая частота ядра.

- Total constant memory - объём постоянной памяти.

- Compute capability - вычислительная способность GPU.

- Texture alignment - выравнивание текстур в памяти.

- Device overlap - поддержка перекрытия вычислений и копирования данных.

- Multiprocessor count - количество мультипроцессоров (SM) на устройстве.

- Kernel execution timeout enabled - наличие ограничения времени выполнения ядер.

### Выводы о производительности видеокарты

Видеокарта **NVIDIA GeForce RTX 3080** (Compute Capability 8.6) обладает высокой вычислительной мощностью и поддерживает современные возможности CUDA.  
Основные характеристики: 68 мультипроцессоров, 10 ГБ глобальной памяти, 48 КБ shared memory на блок, до 1024 потоков на блок.

Основное ограничение - объём памяти 10 ГБ, которого может быть недостаточно для очень больших моделей.

## Формулировка задания по Лабораторной работе 1

Выделить на GPU массив arr из 10^9 элементов типа float и инициализировать его с помощью ядра следующим образом: **arr[i] = sin((i%360)*Pi/180)**. 
Скопировать массив в память центрального процессора и посчитать ошибку **err = sum_i(abs(sin((i%360)*Pi/180) - arr[i]))/10^9**. 
Провести исследование зависимости результата от использования функций: sin, sinf, __sinf. Объяснить результат. Проверить результат при использовании массива типа double.

---

## Реализация

- Для `float` использовались три ядра на GPU:
  - `__sinfKernel_fast` → использует `__sinf`
  - `sinfKernel` → использует `sinf`
  - `sinKernel` → использует `sin` с приведением к `float`
- Для `double` использовалось ядро `sinKernel_double`, использующее стандартную `sin`.
- После вычисления на GPU массив копируется на CPU, и на CPU считается абсолютная ошибка относительно точного значения `sin` в `double`.
- Используется модуль `(i % 360)`, поэтому всего 360 уникальных значений.

---
## Измерение времени

* Время выполнения ядра измерялось с помощью CUDA Events.

* Время копирования данных с GPU на CPU также фиксировалось.

## Сравнение результатов

| Функция | Время ядра (мс) | Время копирования (мс) | Ошибка |
|---------|-----------------|------------------------|--------|
| `__sinf` | 274.413          | 358.199                | 1.276274e-07    |
| `sinf`   | 308.620         | 334.756                | 4.362695e-08    |
| `sin`    | 137.862        | 690.398                | 0.000000e+00    |
| `double sin` | 134.493      | 1595.112             | 9.319320e-18    |

---

1. **Точность**
   - Для float ошибка минимальна у sin (0), чуть выше у `sinf` и `__sinf`
   - Для double ошибка практически нулевая, что ожидаемо, так как double обеспечивает большую точность

2. **Время выполнения**
   - Для float ядро `sin` работает быстрее всех, но время копирования данных у `sin` значительно выше
   - `sinf` и `__sinf` медленнее по времени выполнения ядра, но копирование данных быстрее, чем у `sin`
   - Для double ядро работает примерно так же быстро, как sin для float, но копирование данных занимает заметно больше времени из-за размера double-массива

3. **Вывод**
   - Использование `__sinf` или `sinf` даёт небольшую потерю точности, но может быть выгодно при оптимизации производительности
   - Для задач, где требуется высокая точность, лучше использовать double или стандартную функцию `sin`
