### Пояснения к полученным параметрам

- Device has Compute Capability — вычислительная способность GPU, определяет поколение архитектуры (важно при выборе версии CUDA и совместимости).

- Device name - название видеокарты.

- Total global memory - объём глобальной памяти GPU.

- Shared memory per block - объём разделяемой памяти, доступной на один блок потоков.

- Registers per block - количество регистров, доступных на блок.

- Warp size - размер варпа (группы потоков, исполняемых одновременно).

- Max threads per block - максимальное число потоков в одном блоке.

- Max threads dimensions - допустимые размеры блока по осям X, Y, Z.

- Max grid size - максимальные размеры сетки блоков.

- Clock rate - тактовая частота ядра.

- Total constant memory - объём постоянной памяти.

- Compute capability - вычислительная способность GPU.

- Texture alignment - выравнивание текстур в памяти.

- Device overlap - поддержка перекрытия вычислений и копирования данных.

- Multiprocessor count - количество мультипроцессоров (SM) на устройстве.

- Kernel execution timeout enabled - наличие ограничения времени выполнения ядер.

---

### Выводы о производительности видеокарты NVIDIA GeForce RTX 3080

1. **Высокая вычислительная способность**: Compute Capability 8.6 указывает на архитектуру Ampere, современное поколение GPU с поддержкой всех функций CUDA последних версий.

2. **Большой объём памяти**: 10 ГБ *глобальной памяти* и 64 КБ *постоянной памяти* позволяют обрабатывать большие наборы данных и хранить константные значения без обращения к основной памяти. 49 КБ *разделяемой памяти* на блок обеспечивает быструю локальную работу потоков внутри блока.

3. **Параллельность**: 68 мультипроцессоров (SM) и warp size 32 позволяют одновременно запускать тысячи потоков. Максимум 1024 потока на блок и размеры сетки до 2 млрд по X и 65 тыс по Y/Z обеспечивают гибкую организацию параллельных вычислений.

4. **Высокая тактовая частота**: 1710 МГц ядра гарантирует быстрые вычисления на поток.

5. **Гибкость работы с памятью и вычислениями**: Поддержка Device overlap = 1 позволяет перекрывать копирование данных и вычисления ядра для повышения производительности. Texture alignment = 512 оптимизирует работу с текстурами и кэшированием.

6. **Ограничения**: Kernel execution timeout enabled = true означает, что длительные вычисления на GPU могут быть прерваны.

## Формулировка задания по Лабораторной работе 2
 	
Реализовать программу для накладывания фильтров на изображения. Возможные фильтры: размытие, выделение границ, избавление от шума. Изменить время
Для работы с графическими файлами рекомендуется использовать libpng (man libpng). Примеры использования библиотеки в /usr/share/doc/libpng12-dev/examples/
Считать изображение из файла, преобразовать в массив, отправить на CUDA Device, провести на устройстве обработку фильтром, вернуть изображение в память хоста, преобразовать в картинку, сохранить файл.

## Реализация

**Структура для изображения**

``` C
struct Image {
    int width;
    int height;
    unsigned char *data;
};
```

* Хранит ширину и высоту изображения.

* data - указатель на массив пикселей RGBA (по 4 байта на пиксель: R, G, B, Alpha).

**Ядра CUDA**

1. *Сильное размытие 5x5*

```C
__global__ void strongBlurKernel(unsigned char* input, unsigned char* output, int width, int height) { ... }
```
   * __global__ - cпецификатор CUDA, означающий что функция выполняется на GPU и вызывается с CPU

   * **Параметры:** input - входное изображение в памяти GPU, output - выходное изображение в памяти GPU, width, height - размеры изображения

   * **Вычисление координат:** 
   ```C
   int x = blockIdx.x * blockDim.x + threadIdx.x;
   int y = blockIdx.y * blockDim.y + threadIdx.y;
   ```
   Пример: Для изображения 64×64:

   Блоков по X: (64 + 16 - 1) / 16 = 4

   Блоков по Y: (64 + 16 - 1) / 16 = 4

   Всего блоков: 4 × 4 = 16

   Всего потоков: 16 × 256 = 4096

   * Осуществлена проверка границ

   * Ядро свертки 5×5 -  Гауссово ядро = центральные пиксели имеют больший вес, сумма всех весов = 1.

2. *Умеренное размытие 3x3*  

   * Аналогично сильному размытию, но использует ядро 3×3

3. *Добавление гауссового шума*

   * Генерируется шум для каждого пикселя

   * Формула для псевдослучайного шума: noise_seed = (x*123 + y*456 + seed) % 123456

   * Добавляем ±25 к каждому цвету

**Чтение и запись PNG**

``` C
Image readPNG(const char* filename) { ... }
```

* Использует libpng через png_image

* png_image_begin_read_from_file - начало чтения

* PNG_FORMAT_RGBA - чтение 4х каналов

* Выделение памяти под массив пикселей 

* png_image_finish_read - чтение данных

* Возвращение структуры Image

``` C
void writePNG(const char* filename, Image img) { ... }
```

* Запись изображения в PNG

* png_image_write_to_file - функция записи

**Применение фильтра на GPU**

``` C
void applyFilterGPU(Image input, Image* output, const char* filterType, int kernelSize) { ... }
```

* Вычисление размера данных: size = width * height * 4

* Создание событий для измерения времени: cudaEvent_t startTotal и тд

* Выделение памяти на GPU:

``` C
cudaMalloc(&d_input, size);
cudaMalloc(&d_output, size);
```

* Копирование данных на GPU с помощью cudaMemcpyэ

* Настройка размера блоков и сетки:

``` C
dim3 blockDim(16,16);
dim3 gridDim((width+15)/16, (height+15)/16);
```
   - blockDim - сколько потоков в блоке
   - gridDim - сколько блоков нужно, чтобы покрыть все пиксели

* Запуск ядер CUDA 

* Ожидание завершения вычислений cudaDeviceSynchronize

* Копирование результата на хост

* Подсчет времени выполнения

* Освобождение GPU-памяти и событий

**main() функция**

* Чтение изображения

``` C
Image input = readPNG("cube.png");
```

* Создание памяти для выходных изображений

* Применение фильтров

* Сохранение результатов в PNG

* Осовбождение памяти

* Сброс GPU - cudaDeviceReset()

## Анализ результатов

### Производительность фильтров

1. **Умеренный фильтр 3x3**

| Операция           | Время (ms)       |
| ------------------ | ---------------- |
| Host -> Device copy | 6.537            |
| Kernel execution   | 0.139          |
| Device -> Host copy | 1.807            |
| Total GPU time     | 8.483          |

* Наибольшее время уходит на копирование данных из CPU в GPU

* Само ядро CUDA (размытие) выполняется очень быстро

* Передача данных обратно (D2H) занимает примерно в 13 раз больше времени, чем само вычисление

2. **Сильное размытие 5x5**

| Операция           | Время (ms)         |
| ------------------ | ------------------ |
| Host -> Device copy | 1.024             |
| Kernel execution   | 0.074              |
| Device -> Host copy | 1.785              |
| Total GPU time     | 2.883             |

* По сравнению с предыдущим фильтром, здесь значительно меньше время передачи данных на устройство

* Само ядро выполняется ещё быстрее (0.074 мс) - вероятно, используется более эффективная реализация ядра размытия.

* Общая производительность высокая, время GPU-обработки почти в 3 раза меньше, чем для умеренного размытия.

3. **Добавление шума**

| Операция           | Время (ms)         |
| ------------------ | ------------------ |
| Host -> Device copy | 1.152              |
| Kernel execution   | 0.097            |
| Device -> Host copy | 1.684              |
| Total GPU time     | 2.933            |

* Добавление шума также выполняется очень быстро, что объясняется простыми арифметическими операциями над пикселями.

* Основное время уходит на передачу данных между CPU и GPU, а не на вычисления.
